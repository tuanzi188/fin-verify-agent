# 结构化任务清单

## 目的与边界

将问题中可识别的公司、期间、指标和明确指定的报表口径记录成待查项。
每次读取后更新证据坐标，下一轮只针对缺口补查，避免将模型的口头自检当成完成状态。
清单不额外调用模型、不读取金标、不改变工具清单，也不宣称已经认证答案语义。

实现位于 `backend/app/finance/task_plan.py`；每次运行独立创建，工具集 `prepare()` 清除旧状态。

## 状态与证据

- 待查项：`pending`、`evidence_found`、`conflict`。
- 整体：`incomplete` 表示已知项缺失或存在冲突；`covered` 表示已知证据项覆盖；
  `untracked` 表示没有识别出可以机械跟踪的科目，不能解释为任务已完成。
- 保存公司、期间、指标、显式口径、季度以及实际表、行、列、值和单位。
- 只接受实际读取的目标行列；定位结果、截断结果、疑似错位结果不计为完成。
- 用目标列识别期间，不用年报年份替代目标列年份；明确母公司或合并口径时按原标签匹配。
- 科目名称采用严格归一化匹配，不把研发费用替代研发投入，不把营业总成本替代营业成本。
- 同一待查项出现不同值、单位或口径时记冲突；同值跨金额单位先换算再比较。
- 显式计算要求单列记录。计算调用已发生不代表公式、输入口径已通过验证，仍走原有计算校验。

## 循环与交付

初始提示和每轮工具回填均包含精简清单；完整状态只在最终结果中保留。
连续三次工具调用没有新增定位、证据或不同计算时停止空转，最终回答仍须明确资料缺口。
步数和轮次预算继续生效，不因清单额外启动模型。

线上范围检查已负责真正需要澄清的情况，进入执行器的普通查证请求不再统一标成澄清任务，
从而保留覆盖补查、单元格补取与自检。评测中的明确澄清任务仍保留原语义。

最终 `result.task_plan` 写入 `response.verification.task_plan`，随会话历史保存。
回答声称完成但清单仍为 `incomplete` 时，线上状态降为 `needs_review`；
离线确定性检查增加 `task_plan_complete`，诚实拒答不因未取得证据被额外罚分。

## 受控范围

当前跟踪常用、可直接对应表格行的指标。长文本语义、复杂派生率及未识别科目仍需独立评测，
不能把已识别待查项覆盖率解释成所有子问题都回答正确。
普通读数清单按公司、期间、指标组合展开，复杂的非对称多子问题应补充专门任务后再扩展解析。
本轮不增加跨请求长期记忆，不新增前端任务卡，不改历史评测产物。

## 验证与同预算消融

离线回归：

```bash
cd backend
python -m pytest tests/test_task_plan_runtime.py tests/test_eval_evidence_integrity.py -q
python -m pytest -q
```

真实模型实验必须先报预算并获授权；先使用同一开发题子集、同模型、同工具、同运行次数，
只改变 `--disable-task-plan`，不消耗留出集。下列命令只是复现入口，不代表已执行：

```bash
python -m evaluation.run_finance_eval --tasks <开发题子集> --variant improved --runs 3 --out <启用清单产物>
python -m evaluation.run_finance_eval --tasks <同一开发题子集> --variant improved --runs 3 --disable-task-plan --out <关闭清单产物>
```

默认检索模式与产品一致为 `blocks`，历史 `sections` 复现必须显式传参。
产物绑定 `task_plan_enabled` 与 `task_plan_version`；比较通过率时同时报告成本、延迟、
未完成项和无进展退出，禁止把本轮离线测试通过写成模型能力提升。
