# KnowledgeMind 评测升级方案：RAG 评价与 Agent 测评

> **来源**：2026-10-31 基于《大模型应用/算法学习路线+八股+面试实战》（合并版）评测章（第 5 章）、RAG 章节（13.3 / 13.5）、SmartAppointment 评估模块（1.2.4）与本项目现状的对照分析。
> **状态**：Phase 0 已实施；答案层真实运行、忠实度与最终 Release Gate 校准待后续探针。
> **成本纪律**：全文遵循项目既定纪律——离线优先、探针先行、真实模型复跑先报预算。Phase 0 全部为零 judge token 的确定性计算。

---

## 0. 一页结论

1. 当前评测全部压在**答案层**（judge + 双轨引用 + 证据增量），**检索层无指标、闸门层未建**，是两个明确空位。
2. RAG 评价补检索层：检索段指标（HitRate/MRR）+ 路由准确率 + RAGAS 忠实度——前两项**零 judge 成本**。
3. Agent 测评补闸门层：误拒率进 Release Gate、失败自动归类、Pass@k 稳定性口径、Case Schema 扩展、五类发布闸门。
4. 落地顺序：Phase 0（零成本，~1 天）→ Phase 1（探针级成本）→ Phase 2（与 Release Gate 同期）。
5. 明确不采用：MTEB/BEIR、Elo 对决、大规模用户模拟器、线上监控栈（均与本阶段不匹配，理由见 §2.4 / §3.8）。

## 1. 现状盘点

### 1.1 已有做法（多数与业界标准同构，继续保留）

| 本项目已有做法 | 对应的业界标准概念 | 出处 |
|---|---|---|

| 换模型＝重建基线，不可拼数 | judge/指标标度不统一（MLflow 1-5、Ragas 0/1、LlamaIndex YES/NO 互不可比） | 笔记 5.3.1 |

### 1.2 缺口（本方案要补的）

- **G1 检索层无指标**：检索对了没有、排序好不好是黑盒；无法区分「没检到」vs「检到了没用上」。
- **G2 路由无指标**：双臂比出了谁更优，但 finance_router 自动选路「选没选对」没有度量。
- **G3 闸门未建**：Component Evaluation + 离线 Release Gate 在计划中未实施；误拒率（拒答修复路径=成本黑洞）未进任何红线。
- **G4 稳定性口径弱**：探针报「3-4 通过」，无法暴露「3 对 1 错」类不稳定，也无区间信息。
- **G5 归因靠人工**：CX-10 式分析是手工 trace 阅读，未固化成自动分类。

## 2. RAG 评价方案（补检索层与路由层）

### 2.1 检索段指标【最高优先级，零 judge 成本】

**定义**（适配结构检索：检索单元＝表/行切片/section，非稠密向量块）：

- **HitRate@K**：金标证据位置（表/行/section）出现在前 K 个检索单元中的题占比。
- **MRR**：金标位置在检索结果中的排名倒数的均值。
- **context precision（适配版）**：返回单元中含金标证据的比例。
- **context recall（适配版）**：该题全部金标位置被取到的比例。

**判据来源**：评测集审计后 **65/104 可回查金标点**（另有 26 个派生点暂不入池，待逐点机检后扩充）。每个金标点记录其出处位置（表/行号/section），即检索段判分所需的全部信息——**无需任何模型调用**。

**双臂同尺**：finance_rag 臂与 Agent 臂内的检索调用用同一个 scorer。产出对比直接可解释：

- Agent 答案更好但 HitRate 更低 → 赢在推理，不赢在检索；
- Agent 臂某类题 HitRate 低 → 检索层问题，优先修检索而不是 prompt。

**诊断价值（直指 CX-10）**：每道失败题先过检索段分岔——

```
失败题
├─ 检索段 miss（金标未被取到）→ 修检索（切片/过滤/召回策略）
└─ 检索段 hit 但答案错/拒答 → 修生成或决策（prompt/judge/拒答逻辑）
```

当前 CX-10（拒答修复路径，16 步占 38% 成本）属哪一类，跑一次 Phase 0 即有数据答案。

**实现落点**：4 题探针 harness 内、现有 judge 打分**之前**插入确定性 scorer；读取 provenance 既有位置信息，不新增采集。

### 2.2 路由准确率（finance_router）【零 judge 成本】

- **定义**：strategy=auto 时 router 选中的臂 与 「该题已知更优臂」的一致率；分类视角下报 Macro-F1（两类：走 RAG / 走 Agent）。
- **「已知更优臂」来源**：双臂已跑过的题（compare_arms 既有数据）＋金标判定，无需新增运行。
- **为什么重要**：产品逻辑是「简单查数走 RAG、复杂走 Agent」（10/30 定稿）。router 错选直接造成「简单题烧 Agent 成本」或「复杂题拿 RAG 的差答案」——这是自动选路产品的第一质量指标，目前没有度量。

### 2.3 RAGAS 忠实度【可选，低价并跑】

- **计算**（两步，无需参考答案）：① 让模型把答案拆成若干原子陈述；② 逐条判断「能否仅从本次召回内容推断出该陈述」，可推断数 / 总数即忠实度。
- **用途**：给双臂一把统一的生成质量尺子（检索段指标之外的生成段补充）；与现有 judge **并跑校准**，不一致的样本进入人工复核队列——正好服务评测集审计的「无答案等价规则」缺口。
- **成本控制**：只在探针级（4 题 × 2 臂）并跑，不进全量。
- **注意**：RAGAS 原生面向稠密块检索，本项目检索单元是结构切片，faithfulness 判定文本改为「该题实际注入上下文的切片内容」即可，算法不变。

### 2.4 明确不采用（及理由）

| 项 | 理由 |
|---|---|
| MTEB/BEIR embedding 基准 | 本项目为 BM25+结构检索，无 dense embedding，指标无对象 |
| 纯文本切块策略对比（滑窗等） | 检索单元是结构化切片，切块评测不适用；切片改动时用 §2.1 指标做前后回归即可 |
| Elo/比较式评估 | 单系统无排名需求，双臂 Lab 对比已覆盖 |
| 大规模用户模拟器（POMDP 级） | 美团量级工程投入，与 4 题探针纪律和成本约束不匹配 |

## 3. Agent 测评方案（补闸门层与过程层）

### 3.1 判分纪律（总纲，先于一切指标）

> **能用确定性规则判分的不用 judge；开放式输出先 embedding/事实一致性，最后才用 LLM-judge；judge 必须固定 rubric + 逐档定义 + few-shot 样例 + JSON 强制输出 + 低温（0~0.2）+ 换序去偏 + 定期人工校准。**

本项目现状与前三句一致；查漏项：rubric 逐档定义与 few-shot（见 3.2 的等价规则）。

### 3.2 答案等价规则 + 稳定性口径【补 G4 与审计缺口】

**答案等价 Rubric（原子判据，全有或全无）**——直接补评测集审计发现的「无答案等价规则」缺口：

- 数值一致（含单位与口径）
- 来源一致（指向同一张表/同一份披露文件）
- 结论方向一致（增/减/持平）
- 拒答合理性（证据不足时的拒答属正确行为，计 Pass——与误拒率指标联动）

每条判据在评测集文档中配 1-2 个正反例（few-shot），judge 提示词引用之。

**稳定性口径升级**：

- 同一配置重复 N 次（当前 N=4），汇报 **Pass@4**（至少一次成功）与 **Pass^4**（全部成功）两个数，替代「3-4 通过」的模糊表述；
- 连续型指标（token/步数/得分）报 **均值 ± 标准差 + P95**，不报单次最好——尾部（CX-10 型 case）靠 P95 自动暴露，替代事后人工归因。

### 3.3 误拒率进 Release Gate【成本问题翻译成质量红线】

- **定义**：false refusal rate —— 证据充分（检索段 hit 且金标可答）却拒答的题占比。
- **现状**：拒答修复路径（CX-10）占 38% 成本，但「拒答」本身没有质量指标，只有 token 消耗。
- **动作**：Release Gate 显式加一行 `误拒率 ≤ 阈值`（初始建议值待 Phase 0 数据出来定，如 ≤10%）；拒答题必须附检索段判定（miss→可接受拒答；hit→计误拒）。
- **叙事收益**：成本黑洞从「烧钱问题」变成「质量指标问题」，与业界标准对齐。

### 3.4 失败自动归类【补 G5，把人工归因固化成代码】

从 trace 自动把每道失败题分入固定类别（SmartAppointment 分类学，适配本项目）：

| 类别 | 判定依据（trace 特征） |
|---|---|
| 路由错误 | auto 模式选错臂（对照 §2.2 金标） |
| 检索无命中 | 检索段 miss（对照 §2.1） |
| 工具/参数错误 | 工具名错、必填参数缺失、编造参数、参数值错 |
| 无效循环 | 同一工具同参数重复调用、步数超上限 |
| 过早结束/误拒 | 未穷尽检索即拒答；或检索段 hit 却拒答 |
| 上下文污染 | 引用了与问题无关的先前切片 |
| 权限越界 | 访问了题面之外的数据范围 |
| 模型异常 | API 失败、超时、格式不合规 |

**产出**：每轮探针自动输出失败分布（各类占比），替代人工 trace 阅读；新增类别可扩充。CX-10 归因从此变成例行输出。

### 3.5 Case Schema 扩展【评测集升级，配合审计整改】

每条评测样本在现有字段（问题/金标答案/引用）之外增加：

- `expected_source`：金标位置（表/行/section）——§2.1 判据
- `route_target`：路由设计目标，取 `agent` / `structured_rag` / `indeterminate`；
  `indeterminate` 不进入路由准确率分母，只报告实际分流；旧 `expected_arm` 仅兼容历史报告
- `allowed_tools` / `forbidden_actions`：允许与禁止的工具行为
- `max_steps` / `token_budget`：该题的过程与成本上限（逐 case，而非只有全局阈值）
- `final_state`：可程序化验证的终态字段（如应引用的表名、应给出的数值）
- `retrieval_hops`：证据跳数；`single_hop` 指一个证据单元完成，不限制答案包含几个字段
- `answer_operations`：`lookup` / `compare` / `calculate` / `abstain` / `clarify` / `recover` 等答案操作
- `prompt_style`：`open_question` 或 `direct_constraint`，用于分开解释带明确约束的题面

**可重复回放保障**：数据快照机制已有（检索实现统一 12/12），延续即可。

### 3.6 轨迹评测【按需，暂不全面铺开】

五档松紧（精确匹配 → 按序匹配 → 任意顺序 → 精确率/召回率 → 单一工具）中，本项目先只用两档：

- **按序匹配**：定义每题「关键动作序列」（如：拒答前必须已调用切片检索），trace 比对；
- **单一工具判定**：关键工具（如 get_rows）调用正确性单独出指标。

其余档位等 Release Gate 建立后再议。

### 3.7 五类发布闸门【离线 Release Gate 施工图】

| 闸门 | 测法 | 阈值形态 | 初始建议 |
|---|---|---|---|
| 质量 | 端到端成功率、事实一致性、忠实度（§2.3） | 成功率 / Pass^4 / 一致性分 | 成功率≥金标基线−2pp |
| 轨迹 | §3.6 两档 + §3.4 失败分布 | 错工具率、最大步数、无效循环率 | 无效循环=0 |
| 成本 | 逐轮 token 归因（已有） | 单题 token 预算、P95 token/步数 | 单题≤[探针实测P95]，红线=预算上限 |
| 安全/合规 | 数字幻觉率（数值与金标不一致率）、PII 检查 | 事实一致性、幻觉率 | 数值幻觉率=0（金融场景硬红线） |
| 业务可用性 | **误拒率**（§3.3）、拒答率 | 误拒率阈值 | ≤10%（待 Phase 0 校准） |

任一闸门踩线不发布；阈值随金标扩充和审计整改滚动修订。

### 3.8 暂缓项

- **压测/SLO/四黄金信号**（笔记 9.2.1）：无真实流量，premature；面试素材价值高，工程价值暂无。
- **线上监控栈（logs/traces/metrics 平台、MTTD/MTTR）**：同上；「回灌闭环」思想已被「离线优先」纪律覆盖。
- **多 Agent 协作评测**：本项目当前非多 Agent 架构；若未来引入子 Agent 再启用交接链/消融方法。

## 4. 落地路线图

### Phase 0：零成本确定性指标（~1 天，不烧 judge token）

1. 检索段 scorer（HitRate@K / MRR / precision / recall）接入 4 题探针 harness，双臂同尺；
2. 路由准确率统计（基于既有 compare_arms 数据，不新增运行）；
3. 汇报口径升级：Pass@4 / Pass^4 + 均值±标准差 + P95。

**产出**：首个「答案层 × 检索层 × 路由层」三层报告；CX-10 的 miss/hit 分岔判定。

### Phase 1：探针级低价（随下一轮迭代）

4. RAGAS 忠实度并跑（4 题 × 2 臂），与现有 judge 校准；
5. 答案等价 Rubric 成文（原子判据 + few-shot），进评测集文档；
6. 失败自动归类 v1（先覆盖：检索无命中/工具参数错误/无效循环/误拒 四类，占已知失败的大头）。

### Phase 2：与 Release Gate 同期

7. Case Schema 扩展（随评测集审计整改一起做）；
8. 五类闸门定阈值并固化（误拒率、数字幻觉率两条硬红线先立）；
9. 轨迹按序匹配（如有关键动作序列的题）。

**预算注记**：Phase 0 无模型调用；Phase 1 新增调用 ≈ 4 题 × 2 臂 × 2 次（拆陈述+判推断）≈ 16 次轻量调用/轮；Phase 2 主要是工程与文档工作。任何真实模型复跑前仍按纪律报预算上限。

## 5. 面试叙事（四层评测故事）

> **「你们怎么评测这个 Agent 系统？」**

按层作答，每层有指标、有数字、有决策：

1. **检索层**：金标位置级 HitRate@K / MRR，双臂同尺——「先区分没检到还是没答对，避免把检索问题当成 prompt 问题修」；
2. **路由层**：router 选臂一致率——「自动选路产品的第一质量指标，错选直接造成简单题烧钱」；
3. **答案层**：LLM-judge（rubric 逐档+few-shot+JSON+换序去偏）＋双轨引用＋证据增量，judge 扰动与盲复标防偏见；金标 65/104 可回查、分 gold_verified/judge_only；
4. **闸门层**：五类发布闸门，其中金融场景两条硬红线——数值幻觉率=0、误拒率≤阈值；成本红线（单题 token 预算、P95）并列。

加分细节（真实数据背书）：+16.7pp 首轮提升、探针 −28.6% 成本、trace 否决「重复读表」假设（精确重复读=0）、成本集中在拒答修复路径（38%）→ 由检索段指标判定 miss/hit 分岔。
