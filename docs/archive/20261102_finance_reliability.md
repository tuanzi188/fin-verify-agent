# 金融查证可靠性修复记录

本轮重点是结论、引用、计算与原文之间的确定性校验。历史通用制度库评测分数不能作为本轮金融产品准确率。

## 已实现

- 统一解析 `[1,2]`、`【1、2，PDF 第 49 页】` 等引用。重复证据去重后同步改写正文编号，避免要点丢失引用。
- 百分数纯加减的原始小数结果按正确尺度展示为百分点；例如 `30%-20%` 返回展示值 `10 pp`、`result_scale=100`。已乘百的公式不会再次放大。
- 成功计算按顺序获得编号，模型可用 `[计算1]` 明确绑定。旧格式仅在存在派生语义、完整数值和单位匹配且候选唯一时兼容绑定，不采用数字子串匹配。
- 计算记录补充逐项输入来源，包含证据、表格、行列与原始单元格值。同值出现多个坐标时不猜来源，记录为未完整验证。
- 正式 Agent 与结构 RAG 响应均校验引用完整性、数字和单位。单元格引用的邻近预览不参与目标值校验。无角标回答不再自动绑定全部检索结果。
- 校验未通过返回 `needs_review`，保存校验摘要与要点不确定性。前端实时回答、历史恢复与状态显示均支持该状态。
- 根据当前用户的会话命名空间读取上一轮条件，补全明确的公司、指标和相对年份。多公司、多指标等歧义要求澄清；原始提问与实际查证问题分别保存。
- 公司简称与股票代码由语料清单派生；支持 `2025Q1` 年份识别。未覆盖的明确主体、未来期间及缺少匹配季报的问题在调用模型前说明边界。
- 新入库文档可以关联同页表格下方紧邻的脚注，保留注释区域；证据检查器提供原始披露文件入口，页码可通过 PDF 阅读器定位。

## 校验边界

1. 数值一致性检查不证明指标、主体、会计口径或因果解释在语义上正确；通过自动检查仍需要原文复核。
2. 输入来源只在候选坐标唯一时自动关联。正文来源、同值多坐标和复杂换算输入可能要求人工复核，不会伪造完整溯源。
3. 自动追问补全是本地规则，只支持明确可消歧的公司、指标和年份关系。任意自然语言实体识别与复杂对话仍非完整支持。
4. 季报边界按文档元数据判断；只有年报时保守拒绝直接替代季度披露，可能产生误拒，需要后续专门评测。
5. 脚注关联针对同页、短距离注释，跨页脚注与原 PDF 区域高亮尚未实现。已入库文档需要重新入库才会获得新增脚注字段。
6. 数字表格和超出要点卡范围的数值文本若未进入逐点校验，会被明确标为待复核，避免完整回答绕过检查。

## 验证命令

本轮验收结果：后端 447 项测试通过，前端 57 项测试通过，类型检查通过；新增模块的静态检查通过，OpenAPI 与前端生成类型已同步。浏览器确认主页面加载 7 份文档，未覆盖公司问题返回明确的材料缺失说明，材料页面可正常展示。未调用真实模型批量评测。

本地预览服务保留运行：完整应用为 http://127.0.0.1:8002/ ，静态构建预览为 http://127.0.0.1:8765/ 。静态服务不包含 API，实际查证请使用完整应用地址。

在 `backend` 下执行：

```powershell
D:\python\python.exe -m pytest -q
D:\python\python.exe scripts/generate_schema.py
```

在 `frontend` 下执行：

```powershell
npx openapi-typescript openapi.json -o src/api/generated.ts
npm run typecheck
npm test
npm run build
```

本机 Windows 的默认压缩构建遇到了 esbuild 删除大型转换临时文件失败；已查阅官方仓库问题记录：
https://github.com/evanw/esbuild/issues/4559 。不修改依赖或生产构建配置，使用以下命令生成本机验收预览：

```powershell
npm run build -- --minify=false --target=esnext
```

该预览构建没有压缩，面向现代浏览器，不等同于默认生产构建成功。真实模型答案层、独立公司留出测试及数值发布闸门尚未在本轮运行，不据单元测试推导金融准确率。
