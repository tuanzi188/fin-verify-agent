# 2026-11-05 会话记录

## 一、一句话结论

## 二、发现：一个会产出「有页码的错误数字」的缺陷

### 现象

宁德时代 2024 年报「主要会计数据」表（t0007）解析结果：

```
columns: ['项目','col2','2023 年','col4','本年比上年','2022 年','col7','调整后','col9']
row 0:   ['', '营业收入（千元）', '362,012,554', '400,917,045', '-9.70%', ...]
```

```
get_cell(t0007, "营业收入（千元）", "2024 年") → 找不到列
get_cell(t0007, "营业收入（千元）", "2023 年") → 362,012,554   ← 这是 2024 年的值
```

2023 年的真实值是 400,917,045。系统会产出「宁德时代 2023 年营业收入为 362,012,554 元」——**年份错、单位错（应为千元），但页码、表 id、行名、bbox 全部真实，所有闸门都会放行。**

### 根因

`_align_columns` 假设表头行和数据行共享列索引，只做全局 ±1 位移。这张表的表头是**分段错位**的：

| 表头 | 正确位移 |
|---|---|
| 左半段（2024 年 / 2023 年） | 0 |
| 右半段（本年比上年 / 2022 年） | −1 |

打分函数按"表头名落在有数据的列上"求和，右半段表头更多，于是选了 −1（3.16 vs 1.91），把 `2023 年` 落到 2024 的值上。

原始网格（pymupdf `extract()`）里，`2024 年` 的 bbox 与 `362,012,554` 的 bbox 完全重合，只是网格索引把它们分开了。

## 三、三处修复

### 1. 按单元格坐标重建列（`_split_table_by_cells`）

- 列由非空数据单元格的 x 区间聚类决定，不再依赖网格索引
- 锚点：数字取右边界（右对齐），文本取左边界（左对齐），容差 8pt
- 表头按"覆盖列中心"拼成层级：`2022 年` + `调整前` → `2022 年调整前`
- 段中第二段表头（`项目｜2024 年末｜…`）用 `_is_header_like_row` 排除，不参与建列
- **只在网格结果出现 `colN` 占位名时触发**；规整的表保持旧行为

### 2. 跨页财务报表合并（`_is_statement_continuation`）

旧逻辑只接 ≤4 行的碎片，资产负债表/利润表/现金流量表每页几十行，一律不接，于是每页变成一张无表头的独立表。

新规则需同时满足：首表列名像报表（`项目` 前缀 + 期间列 + ≥3 列）、页码相邻、续页无标题、x 对齐、首表触底且续页顶格、首行是数据行、列数可对齐（多一列前导空列时按标签分布裁剪，并搬回落错位的行名）。

### 3. 表单位（`count_repeated_lines` + 续页继承）

根因不在 `_unit_for`，而在 `count_repeated_lines`：`单位：千元` 在几十页重复出现，被判定为页眉页脚剔除，`_unit_for` 永远找不到它，单位回退成文档默认「元」。

修复：单位声明行不参与重复行统计；续页按"相邻 + 无标题 + 列数一致"继承上一张表的单位。

## 四、新增：证据流分析器（`evaluation/evidence_flow.py`）

零 token、不需要任务卡，只读 runs 产物的 `trace` / `evidence` / `citations`。补上 `trajectory_eval` 之外的过程指标：

- `locator_to_reader_rate`：定位到的表/节实体中，被读取工具碰过的比例
- `read_evidence_rate`：读取步中真正新增证据的比例
- `uncited_read_rate`：读过的实体未出现在最终引用里的比例
- `redundant_read_steps`：实体已读过且本轮无新增证据的重复读取
- `first_locator_hit` / `first_read_hit`：首轮定位/读取是否最终被引用
- `failed_calls` / `failure_recovery_rate`：工具失败与恢复

11 题 blocks 产物读数（**unverified，本地单次**）：定位→读取 22.8%、读取有效 74.5%、读了没引 6.9%、重复读取 13.8%、首轮定位命中 100%、失败恢复 100%。
