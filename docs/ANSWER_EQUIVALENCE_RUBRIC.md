# 答案等价规则（Answer Equivalence Rubric）

> 目的：把“65.7084 / 65.71 / 约 65.7 算不算同一个答案”写死，避免 judge 凭感觉判、
> 也避免评测集审计里“没有答案等价规则”这个缺口一直悬着。
>
> 代码实现：`backend/evaluation/equivalence.py`（确定性数值等价）+
> `backend/evaluation/agent_judge.py`（rubric 进 judge prompt）+
> `backend/evaluation/numeric_audit.py`（金标覆盖率 / 数值幻觉）。
>
> **few-shot 的单一维护点**：下表 9 条例子由 `equivalence.py` 的 `FEWSHOT_TEXT`
> 提供，`rubric_text()` 把它拼进 judge prompt。本文档描述口径，改例子改代码；
> 不要在两处各维护一份。容差仍只改 `DEFAULT_REL_TOLERANCE`。

## 四条原子判据（全有或全无）

一个答案要点只有在下列**全部适用判据**都满足时，才记 `pass`。
判据不适用的（例如要点文本里没写方向）记 `None`，不记失败。

### 1. 数值一致（含单位与口径）

- 允许千分位：`456,451,731` = `456451731`；
- 允许百分号/全角百分号：`12.11%` = `12.11％`；
- 允许括号负数：`(1,234)` = `-1234`；
- 允许金额跨单位：`456,451,731 千元` = `4,564.52 亿元`；
- 允许合理舍入：相对差 ≤ **0.05%**（`65.7084%` = `65.71%`）；
- **不允许**把 `9.08` 与 `9.09` 判成同一个值（相对差约 0.11%，超容差）；
- **不允许**百分比与小数互换算：`29.90%` ≠ `0.299`（口径不同，必须由答案说明）。

### 2. 来源一致

- 指向同一张表或同一份披露文件；
- 同一数字出现在不同表里但口径不同（合并/母公司、本期/上期、分部/整体）不算来源一致；
- 引用锚点必须能解析到真实 chunk，且该 chunk 支撑该要点。

### 3. 结论方向一致

- 增长 / 下降 / 持平必须一致；
- 把“下降 33.46%”说成“增长 33.46%”，即使数字对也判失败；
- 要点文本没写方向时，本判据不适用。

### 4. 拒答合理性

- 资料确实不足时，明确说明“现有资料无法确定”属正确行为，计 `pass`；
- 资料里明明有答案却拒答，不计 `pass`（误拒，进 Release Gate 的业务可用性红线）。

## Few-shot

### 正例（判 pass）

| 期望 | 回答 | 理由 |
|---|---|---|
| `456,451,731 千元` | `约 4,564.52 亿元` | 金额跨单位换算一致，舍入在容差内 |
| `65.7084%` | `约 65.71%` | 相对差 2.4e-5，合理舍入 |
| `9.09 个百分点` | `高 9.09 个百分点` | 数值、单位、方向都一致 |
| `资料未披露` | `根据现有资料无法确定` | 证据不足时的诚实拒答 |

### 反例（判 fail）

| 期望 | 回答 | 理由 |
|---|---|---|
| `9.09 个百分点` | `高 9.09%` | 数字对但口径错（百分点 ≠ 百分比） |
| `456,451,731 千元` | `456,451,731 元` | 数字对但单位错（千元 ≠ 元） |
| `下降 33.46%` | `增长 33.46%` | 方向错 |
| `9.09 个百分点` | `高 9.08 个百分点` | 超出舍入容差，是真错误 |
| `营业收入 100 元` | `资料不足，无法确定` | 资料里有答案却拒答（误拒） |

## 口径边界

- 这套规则只覆盖**可确定性判**的部分；来源支撑、拒答合理性仍需 judge 做语义判断。
- judge prompt 里的 rubric 文本与 `equivalence.py` 的容差必须保持同源；
  改容差只改 `DEFAULT_REL_TOLERANCE`，不要在两处各写一份。
- 数值幻觉的硬红线定义是“judge 判 pass 但金标数值缺失”，不是“答案里出现未溯源数字”。
  后者是提示项，因为派生中间值可能合法。
